# Read on reMarkable (Safari)

A Safari extension that sends the article you are reading to your reMarkable, as a
clean **EPUB** (reflowable) or **PDF** (fixed layout). This is the Safari counterpart
to the Chrome "Read on reMarkable" extension.

It extracts the readable article from the page (using Mozilla's Readability, the same
engine behind Firefox Reader View), builds an EPUB or PDF in the browser, and uploads
it straight to your reMarkable cloud account. There is no middle-man server: your
article goes from your Mac to reMarkable directly, and your pairing token is stored
only on your Mac.

---

## What you need

- A Mac with **Safari 16.4 or newer**
- **Xcode** installed (free from the Mac App Store) - Safari extensions must be wrapped
  in a small Mac app and built once
- A **reMarkable account** (the same one your tablet syncs with)

You do **not** need a paid Apple Developer account for personal use.

---

## Folder layout

```
rmsafari/
  extension/        <- the actual Safari Web Extension (this is what Xcode wraps)
    manifest.json
    background.js   <- bundled: reMarkable upload + EPUB/PDF builder
    content.js      <- bundled: article extraction (Readability)
    popup.js
    popup.html
    images/         <- toolbar icons (already generated by make_icons.py)
  appicon/          <- macOS App Icon sizes, for Xcode's Assets.xcassets (optional, see below)
  src/              <- readable source before bundling
  build.mjs         <- rebuilds the bundles in extension/ (run with: node build.mjs)
  make_icons.py     <- regenerates every icon (run with: python3 make_icons.py)
  test/             <- EPUB/PDF build tests (node test/build.test.mjs)
  README.md
```

The `extension/` folder is already built and ready. You only need `build.mjs` if you
want to change the source and rebuild (see "Modifying it" at the end).

## Install it (about 5 minutes)

### 1. Convert the extension into an Xcode project

Open Terminal, `cd` into this folder, and run:

```bash
xcrun safari-web-extension-converter extension \
  --app-name "Read on reMarkable" \
  --bundle-identifier com.yourname.readonremarkable \
  --macos-only \
  --copy-resources \
  --no-open
```

Change `com.yourname.readonremarkable` to anything unique (e.g. use your own name).
This creates a `Read on reMarkable/` project folder next to `extension/`.

### 2. Build it in Xcode

1. Open the generated `Read on reMarkable.xcodeproj`.
2. Select the **app target** (top-left dropdown) named "Read on reMarkable".
3. Go to **Signing & Capabilities**. Under **Team**, pick your personal Apple ID
   (Xcode - Settings - Accounts to add it if needed). "Sign to Run Locally" is fine.
   Do the same for the **extension target** if Xcode flags it.
4. Press **Run** (the play button, or Cmd-R). A small app window opens saying the
   extension is now available in Safari. You can quit that window afterwards.

### 3. Enable it in Safari

1. Open **Safari - Settings - Extensions**.
2. If "Read on reMarkable" does not appear, enable developer signing first:
   - Safari - Settings - **Advanced** - check **"Show features for web developers"**.
   - In the new **Develop** menu, check **"Allow Unsigned Extensions"**.
     (Note: this resets each time you fully quit Safari, so re-check it if the
     extension disappears. Signing with your Apple ID in step 2 avoids this.)
3. Turn on the checkbox for **Read on reMarkable**.
4. Click **Edit Websites** or, on first use, choose **"Always Allow on Every Website"**.
   The extension needs to read the article on the page and fetch its images.

### 4. Pair with reMarkable

1. Click the extension's icon in the Safari toolbar.
2. Open [my.remarkable.com](https://my.remarkable.com/device/browser/connect), sign in,
   and copy the **8-character one-time code** it shows.
3. Paste the code into the popup and click **Connect**. Done, it is remembered.

## Using it

1. Open any article.
2. Click the toolbar icon.
3. Pick **EPUB** or **PDF** (it remembers your last choice).
4. Click **Send this page**.

Within a few seconds it appears in the root of your reMarkable library (it syncs to the
tablet the next time the tablet is online).

**EPUB vs PDF:**
- **EPUB** reflows to the reMarkable screen. You can change the font size and margins,
  and highlighting/annotation works well. Best for most articles.
- **PDF** keeps a fixed page layout with the article's headings, text, and figures.
  Choose it when you want a more print-like page.

## App icon (optional)

The toolbar icon is already baked into `extension/images/`, nothing to do there. If you
also want a matching icon in the Dock/Finder/Xcode (instead of Xcode's default blank
icon), the `appicon/` folder has every size macOS needs:

1. In Xcode's left sidebar, open the app target's files, find **Assets.xcassets**, and
   click **AppIcon**.
2. If you see one big empty box (newer Xcode "single size" icon), drag
   `appicon/master-1024.png` into it, Xcode generates the rest automatically.
3. If instead you see a grid of labeled boxes (16pt, 32pt, 128pt, 256pt, 512pt, each
   with a 1x and 2x slot), drag the matching file into each, using this mapping:

   | Box       | File                |
   |-----------|---------------------|
   | 16pt 1x   | `appicon-16.png`    |
   | 16pt 2x   | `appicon-32.png`    |
   | 32pt 1x   | `appicon-32.png`    |
   | 32pt 2x   | `appicon-64.png`    |
   | 128pt 1x  | `appicon-128.png`   |
   | 128pt 2x  | `appicon-256.png`   |
   | 256pt 1x  | `appicon-256.png`   |
   | 256pt 2x  | `appicon-512.png`   |
   | 512pt 1x  | `appicon-512.png`   |
   | 512pt 2x  | `appicon-1024.png`  |

4. Cmd-R to rebuild. Empty boxes are fine for a local build, they only matter for an
   App Store submission (see below), where Xcode's validator checks all sizes are filled.

Want to change the design? Edit `make_icons.py` and re-run `python3 make_icons.py`,
it writes straight back into `extension/images/` and `appicon/`.

## Distributing it beyond your own Mac

A few things worth knowing before sharing this with anyone else or publishing it:

- **The name "Read on reMarkable" is already taken** by reMarkable's own Chrome
  extension. Sharing a personal build under that name is fine, but for a public GitHub
  release or an App Store listing, pick a different display name to avoid confusion (and
  a likely App Review rejection for a name that isn't yours to use). Rename it by
  changing `--app-name` in the conversion command and the target's display name in
  Xcode, then rebuild.
- **This uses reMarkable's internal cloud API**, the same undocumented endpoints their
  own apps use, not a published developer API. That's how community tools like `rmapi`
  and `rmapi-js` already operate, but it's worth knowing before making this more public:
  Apple's App Review can be cautious about apps built on another company's internal
  API, and reMarkable could change those endpoints without notice.
- **Sharing the built app directly** (a zip of the `.app`, e.g. via GitHub) works without
  paying anything. Apple's own docs describe this as the standard way to beta test a
  Safari extension: whoever you send it to needs to bypass Gatekeeper once (right-click
  the app - Open) and enable **Allow Unsigned Extensions** in Safari's Develop menu (the
  same toggle from step 3 above).
- **A smooth, warning-free install for a wider audience** (a public GitHub release or an
  App Store listing) needs an Apple Developer Program membership ($99/year) to sign and
  notarize the app, or to submit it through App Store Connect.

## Privacy

- Your reMarkable pairing token is stored locally in the extension's own storage on your
  Mac. It is never sent anywhere except to reMarkable's own servers.
- Articles are uploaded directly to `internal.cloud.remarkable.com` (reMarkable's cloud).
  Nothing passes through any third-party server.
- This project is not affiliated with or endorsed by reMarkable. It uses reMarkable's
  cloud API the same way community tools like `rmapi` do.

---

## Limitations

- Images are embedded on a best-effort basis. Some sites block cross-site image loading,
  and those images are simply skipped rather than breaking the document.
- Tables are converted to plain text (reMarkable reading is text-first).
- Pages behind a login or paywall only export what is actually loaded in your browser.
- Very heavy pages (huge galleries) export the article text and figures, not the whole
  page.

---

## Troubleshooting

- **"Couldn't reach the page. Reload the article and try again."** - The content script
  had not loaded yet. Reload the tab and retry. Make sure the extension is allowed on the
  site (Safari - Settings - Extensions - Read on reMarkable - website permissions).
- **"Not connected"** keeps coming back - The pairing code is single-use and expires
  quickly. Get a fresh one from my.remarkable.com and reconnect.
- **Pairing fails** - Codes are 8 characters, all lowercase letters. Copy a brand-new one.
- **Extension vanished after quitting Safari** - "Allow Unsigned Extensions" resets on
  restart. Re-enable it, or sign the app with your Apple ID (step 2) so it sticks.
- **Nothing shows on the tablet** - Confirm the tablet is online and syncing; new items
  land in the library root.

## Modifying it

The readable source is in `src/`. After changing it, rebuild the bundles:

```bash
npm install        # first time only
node build.mjs     # rebuilds extension/background.js, content.js, popup.js
node test/build.test.mjs   # optional: verifies EPUB/PDF generation
python3 make_icons.py      # optional: regenerates every icon size
```

Then rebuild in Xcode (Cmd-R). If you converted with `--copy-resources`, re-run the
converter or copy the updated `extension/` files into the project's
`.../Read on reMarkable Extension/Resources/` folder.

Built with [rmapi-js](https://github.com/erikbrinkman/rmapi-js) (reMarkable cloud),
[@mozilla/readability](https://github.com/mozilla/readability) (article extraction),
[JSZip](https://stuk.github.io/jszip/) (EPUB), and [jsPDF](https://github.com/parallax/jsPDF) (PDF).
